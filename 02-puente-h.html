El puente H (L298N)

El intermediario que faltaba. Ahora sí, el Arduino manda y los motores obedecen.

⏱️ 1h 30 – 2h 🎯 5 desafíos 💻 Primer código
🎯 Al terminar esta parada vas a poder…

  • Hacer que los motores vayan adelante, atrás y que el auto gire sobre su eje.

  • Programar una coreografía completa de movimientos.

🧠 ¿Qué es un puente H?

En la parada 1 descubriste que para invertir un motor hay que dar vuelta los cables. Un puente H es un circuito con cuatro interruptores electrónicos que hacen justamente eso, pero solos y miles de veces por segundo.

Se llama "puente H" porque, dibujado, los cuatro interruptores y el motor en el medio forman una letra H. Cerrando dos interruptores en diagonal, la corriente cruza el motor en un sentido. Cerrando la otra diagonal, cruza al revés.

La corriente siempre baja del + al −, pero cruza el motor en sentidos opuestos según qué diagonal esté cerrada. El módulo L298N trae dos puentes H adentro: uno por motor.

💥 ¿Y si cierro los dos interruptores de un mismo lado?

Conectás el + directo al − sin nada en el medio: cortocircuito. En un puente H hecho a mano eso lo quema. El L298N tiene protección interna para que no pase, pero la idea está buena para entender por qué las combinaciones de pines no son todas válidas.

🟡 Los tres jumpers que confunden a todo el mundo
  • Jumpers de ENA y ENB: vienen puestos de fábrica. Con el jumper puesto, el motor está siempre habilitado a máxima velocidad y no podés regularla. Sacalos los dos y conectá ENA y ENB al Arduino.
  • Jumper del regulador de 5 V (el que está al lado de las borneras de alimentación): dejalo puesto si alimentás con 7,4 V o hasta 12 V. Sacalo si usás más de 12 V, o el regulador se quema.
  • Si le sacás el jumper de 5 V, el pin +5V deja de dar tensión: pasa a ser una entrada. No lo hagas en este proyecto.

🔌 Conexión, parte 1: los cables de órdenes

Del Arduino al L298N van 6 cables de control más la masa. Pasá el mouse por cada fila de la tabla y mirá qué cable se ilumina en el dibujo.

Estos cables llevan órdenes, no potencia. Por eso pueden ser finitos. Los pines ~5 y ~10 tienen tilde: eso significa que saben hacer PWM.

⭐ El cable que todos se olvidan: la masa común

El Arduino y el L298N tienen que compartir el GND. Si no, cuando el Arduino manda "5 V", el L298N no tiene con qué comparar ese 5 V y las órdenes llegan como ruido. El auto hace cosas raras, los motores tiemblan o directamente no pasa nada. El 80% de los "no me anda" es este cable.

🔌 ¿Y el Arduino de dónde se alimenta?

Mientras programás: dejalo enchufado al USB de la compu. La batería solo alimenta el L298N. El cable de masa común hace que se entiendan. Es lo más seguro para probar.

Cuando el auto anda solo: llevá un cable del +12V del L298N al pin Vin del Arduino, y ya tenés el GND compartido. Con la batería de 7,4 V alcanza. Desenchufá el USB antes.

💻 El código: la tabla de verdad del L298N

IN1 e IN2 son como dos interruptores que deciden el sentido del motor A. Las cuatro combinaciones:

IN1IN2El motor…
LOWLOWqueda suelto (gira libre hasta frenarse solo)
HIGHLOWgira en un sentido ➡️
LOWHIGHgira en el otro ⬅️
HIGHHIGHfrena en seco 🛑

Y por encima de todo eso, analogWrite(ENA, 0..255) decide con cuánta ganas lo hace.

Primer programa: que se muevan

02a_primer_movimiento.ino ⬇ .ino 
// ============================================
//  Parada 2 - Primer movimiento
//  Los dos motores para adelante, y frenan.
// ============================================

// Motor izquierdo (canal A del L298N)
const int ENA = 5;   // velocidad (tiene que ser un pin ~)
const int IN1 = 6;   // sentido
const int IN2 = 7;   // sentido

// Motor derecho (canal B del L298N)
const int IN3 = 8;
const int IN4 = 9;
const int ENB = 10;  // velocidad (pin ~)

void setup() {
  // Los 6 pines son salidas: el Arduino manda, no escucha.
  pinMode(ENA, OUTPUT);
  pinMode(IN1, OUTPUT);
  pinMode(IN2, OUTPUT);
  pinMode(IN3, OUTPUT);
  pinMode(IN4, OUTPUT);
  pinMode(ENB, OUTPUT);
}

void loop() {
  // --- Los dos motores para adelante ---
  digitalWrite(IN1, HIGH);   // motor izquierdo: sentido 1
  digitalWrite(IN2, LOW);
  digitalWrite(IN3, HIGH);   // motor derecho: sentido 1
  digitalWrite(IN4, LOW);

  analogWrite(ENA, 180);     // velocidad: de 0 a 255
  analogWrite(ENB, 180);

  delay(2000);               // andar 2 segundos

  // --- Frenar ---
  analogWrite(ENA, 0);
  analogWrite(ENB, 0);

  delay(2000);               // quieto 2 segundos
}
⚠️ Antes de dar play

Levantá el auto o poné el chasis sobre un libro, con las ruedas al aire. Si no, se te escapa de la mesa en el primer intento. (Va a pasar igual, pero al menos que no sea la primera vez.)

Segundo programa: ordenar el código con funciones

Escribir 6 digitalWrite cada vez que querés moverte es un bardo. Metamos cada movimiento en su propia función: el loop() queda que se lee como un cuento. Este archivo lo vas a reusar en todas las paradas siguientes, así que guardalo bien.

02b_funciones_de_movimiento.ino ⬇ .ino 
// ============================================
//  Parada 2 - Funciones de movimiento
//  Guardá este archivo: lo vamos a usar siempre.
// ============================================

const int ENA = 5, IN1 = 6, IN2 = 7;    // motor izquierdo
const int IN3 = 8, IN4 = 9, ENB = 10;   // motor derecho

int velocidad = 170;   // de 0 a 255. Probá cambiarlo.

void setup() {
  pinMode(ENA, OUTPUT); pinMode(IN1, OUTPUT); pinMode(IN2, OUTPUT);
  pinMode(IN3, OUTPUT); pinMode(IN4, OUTPUT); pinMode(ENB, OUTPUT);
  frenar();
}

void loop() {
  adelante();          delay(1500);
  frenar();            delay(500);
  atras();             delay(1500);
  frenar();            delay(500);
  girarDerecha();      delay(800);
  frenar();            delay(500);
  girarIzquierda();    delay(800);
  frenar();            delay(2000);
}

// ---------- Las funciones ----------

void adelante() {
  digitalWrite(IN1, HIGH); digitalWrite(IN2, LOW);
  digitalWrite(IN3, HIGH); digitalWrite(IN4, LOW);
  analogWrite(ENA, velocidad);
  analogWrite(ENB, velocidad);
}

void atras() {
  digitalWrite(IN1, LOW); digitalWrite(IN2, HIGH);
  digitalWrite(IN3, LOW); digitalWrite(IN4, HIGH);
  analogWrite(ENA, velocidad);
  analogWrite(ENB, velocidad);
}

// Gira sobre su propio eje: una rueda adelante, la otra atras.
void girarDerecha() {
  digitalWrite(IN1, HIGH); digitalWrite(IN2, LOW);   // izquierda adelante
  digitalWrite(IN3, LOW);  digitalWrite(IN4, HIGH);  // derecha atras
  analogWrite(ENA, velocidad);
  analogWrite(ENB, velocidad);
}

void girarIzquierda() {
  digitalWrite(IN1, LOW);  digitalWrite(IN2, HIGH);
  digitalWrite(IN3, HIGH); digitalWrite(IN4, LOW);
  analogWrite(ENA, velocidad);
  analogWrite(ENB, velocidad);
}

void frenar() {
  analogWrite(ENA, 0);
  analogWrite(ENB, 0);
}

⚡ ¿Qué es realmente el PWM?

El Arduino no sabe dar 3 voltios. Solo sabe dar 5 V o 0 V. Entonces hace trampa: prende y apaga el pin miles de veces por segundo. Si está prendido la mitad del tiempo, el motor recibe la mitad de la energía y gira a la mitad de velocidad.

Eso es PWM (modulación por ancho de pulso), y es lo que hace analogWrite(pin, valor) con un valor de 0 a 255.

Cuanto más tiempo pasa arriba, más energía recibe el motor.

🤔 Para pensar

Si bajás el PWM demasiado (digamos, 40), el motor zumba pero no gira. ¿Por qué? Pista: pensá en el rozamiento de los engranajes de la caja reductora. El motor necesita un empujón mínimo para arrancar. Ese valor mínimo lo vas a tener que descubrir vos, y no es igual en los dos motores.

🚀 Desafíos

Fácil

Cargá 02a_primer_movimiento.ino con el chasis levantado. Casi seguro que una rueda gira al revés que la otra. Es normal: los motores están montados espejados.

Arreglalo de dos formas distintas y decidí cuál te gusta más:

  1. Por hardware: dando vuelta los dos cables de ese motor en la bornera.
  2. Por software: invirtiendo HIGH y LOW de IN3 e IN4.
¿Cuál conviene?

La de hardware, si podés. Así en el código "adelante" significa siempre lo mismo para los dos motores y no tenés que acordarte de una excepción rara a las 3 de la tarde de la carrera.

Fácil

Cargá 02b_funciones_de_movimiento.ino y comprobá que las cuatro funciones hacen lo que dice su nombre. Si girarDerecha() gira a la izquierda, arreglá el código (o los cables) hasta que los nombres digan la verdad.

Suena a detalle, pero un nombre que miente te va a costar una hora de la parada 4.

Medio

Con el auto apoyado en el piso (no en el aire, el piso tiene rozamiento), bajá velocidad de a 10 hasta encontrar el valor más chico con el que el auto todavía arranca solo. Anotalo, lo vas a necesitar en la parada 6.

Después probá lo mismo con la batería medio descargada. ¿Cambia el número? Ahí tenés por qué un auto que andaba perfecto ayer hoy no arranca.

Medio

Programá una rampa: que el auto acelere de a poco de 0 a 255 en 3 segundos, se mantenga 2 segundos, y frene de a poco. Usá un for.

Ver el esqueleto
idea
for (int v = 0; v <= 255; v = v + 5) {
  analogWrite(ENA, v);
  analogWrite(ENB, v);
  delay(60);
}

Ojo: si arrancás en 0 el motor no se mueve hasta pasar su velocidad mínima. Probá arrancar en el valor que encontraste en el desafío 3.

Difícil

Programá el auto para que recorra un cuadrado de 50 cm de lado en el piso y vuelva más o menos al punto de partida. Cuatro veces: avanzar, girar 90°.

El desafío real no es programarlo: es calibrar los tiempos. ¿Cuántos milisegundos de girarDerecha() son exactamente 90 grados? Solo lo vas a saber probando. Marcá con cinta el punto de largada.

🤔 La pregunta que vale oro

Corré el mismo programa tres veces. ¿Cae siempre en el mismo lugar? Casi seguro que no: se va acumulando error en cada giro. Esa es exactamente la razón por la que existen los sensores. Un robot que solo cuenta el tiempo va a la deriva; uno que mira el mundo se corrige. Bienvenido a la parada 3.

Ver una posible estructura
idea
void loop() {
  for (int lado = 0; lado < 4; lado++) {
    adelante();
    delay(1200);        // ajustar hasta que sean 50 cm
    frenar();
    delay(300);
    girarDerecha();
    delay(450);         // ajustar hasta que sean 90 grados
    frenar();
    delay(300);
  }
  frenar();
  delay(5000);          // pausa antes de repetir
}

🎒 Lo que te llevás de esta parada
  • El puente H invierte la corriente del motor con cuatro interruptores electrónicos.
  • IN1/IN2 e IN3/IN4 deciden el sentido; ENA y ENB, la velocidad.
  • El GND común entre Arduino y L298N no es opcional.
  • Con solo contar tiempo, el robot acumula error. Necesita mirar el mundo. → Parada 3.
