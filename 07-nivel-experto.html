🧭 Antes de entrar

Esta parada asume que el auto de la parada 6 ya da tres vueltas seguidas sin salirse. Si todavía no, volvé: no hay control proporcional que arregle un sensor mal calibrado o un cable flojo. Lo de acá mejora un auto que ya anda; no salva uno que no.

🐌 El problema del auto de 2 sensores

Tu auto solo conoce cuatro estados del mundo. No sabe si se desvió un poquito o muchísimo: en los dos casos hace exactamente lo mismo, corregir a fondo. Eso se llama control on-off (o "bang-bang"), y por eso el auto zigzaguea aunque vaya derecho: siempre está corrigiendo de más y después corrigiendo para el otro lado.

👀 Cuatro ojos ven mejor

Con cuatro sensores el auto ya no responde "hay línea / no hay línea", sino dónde está la línea. Y con eso puede decidir cuánto corregir.

El truco es darle un peso a cada sensor según su posición. Los de los extremos pesan más porque significan un desvío más grande:

Ahora, el error (o sea, cuánto está desviado el auto) es el promedio de los pesos de los sensores que están viendo negro:

📐 Control proporcional: la fórmula

Una sola línea de matemática, y es la idea más importante de toda la robótica de control:

corrección = Kp × error

error: cuán lejos estás de donde querés estar  ·  Kp: cuánto reaccionás por cada unidad de error

Y las velocidades salen solas:

  • velocidadIzquierda = base + corrección
  • velocidadDerecha = base − corrección

Si el error es 0, las dos ruedas van iguales y el auto va derecho. Si el error es −3, la rueda izquierda se frena mucho (incluso va en reversa) y la derecha acelera. Si el error es −1, lo mismo pero suavecito. Esa es toda la diferencia con el auto de 2 sensores.

🎚️ Elegir Kp: el único número que importa
  • Kp muy chico → corrige tímido, se sale en las curvas.
  • Kp muy grande → corrige violento, zigzaguea peor que con 2 sensores.
  • Para empezar: Kp = base / 3. Con base = 150, probá Kp = 50. Después movelo de a 5 y anotá.
🤔 ¿Dónde más viste esto?

Cuando manejás una bicicleta y te desviás un poquito, corregís un poquito. Si te desviás mucho, corregís mucho. Nunca das un volantazo por un desvío mínimo. Eso es control proporcional, y lo venís haciendo desde que aprendiste a andar en bici. Los ascensores, los drones, el aire acondicionado y el piloto automático de los aviones usan esta misma fórmula (con dos términos más, la D y la I, que es el famoso PID).

Los dos internos (S2 y S3) van separados un poco menos que el ancho de la línea: cuando el auto está centrado, los dos la ven. Los externos van bastante más afuera, para avisar cuando el desvío ya es grande.

⚡ Ahora sí necesitás la protoboard

Cuatro sensores son cuatro VCC y cuatro GND. Llevá un cable de 5V y uno de GND del Arduino a la protoboard y repartí desde ahí. Y ojo con el consumo: cuatro módulos IR encendidos consumen unos 100 mA. El regulador del Arduino los banca, pero si además alimentás algo más, mejor sacá los 5V del pin +5V del L298N.

💻 El código con 4 sensores y control proporcional

07_proporcional_4_sensores.ino ⬇ .ino 
// ============================================================
//  SEGUIDOR DE LINEA - 4 sensores + control proporcional
//  Nivel experto
// ============================================================

const int ENA = 5, IN1 = 6, IN2 = 7;
const int IN3 = 8, IN4 = 9, ENB = 10;

// Los 4 sensores, de izquierda a derecha
const int S1 = 2, S2 = 3, S3 = 4, S4 = 11;

const int VE_LINEA = HIGH;

// ---------- AJUSTES ----------
int   VEL_BASE = 150;    // velocidad cuando va centrado
float Kp       = 50.0;   // cuanto corrige por cada unidad de error
int   VEL_BUSQUEDA = 130;

// Memoria: hacia donde estaba yendo la ultima vez que vio la linea
float ultimoError = 0;

void setup() {
  pinMode(ENA, OUTPUT); pinMode(IN1, OUTPUT); pinMode(IN2, OUTPUT);
  pinMode(IN3, OUTPUT); pinMode(IN4, OUTPUT); pinMode(ENB, OUTPUT);
  pinMode(S1, INPUT); pinMode(S2, INPUT);
  pinMode(S3, INPUT); pinMode(S4, INPUT);

  Serial.begin(9600);
  frenar();
  delay(2000);
}

void loop() {
  // ---------- 1. SENSAR ----------
  int s1 = (digitalRead(S1) == VE_LINEA) ? 1 : 0;
  int s2 = (digitalRead(S2) == VE_LINEA) ? 1 : 0;
  int s3 = (digitalRead(S3) == VE_LINEA) ? 1 : 0;
  int s4 = (digitalRead(S4) == VE_LINEA) ? 1 : 0;

  int cuantos = s1 + s2 + s3 + s4;

  // ---------- 2. PENSAR ----------
  if (cuantos == 0) {
    // Perdio la linea: gira hacia donde la vio por ultima vez
    buscarLinea();
    return;
  }

  if (cuantos == 4) {
    // Los cuatro ven negro: cruce o linea de llegada
    adelanteRecto();
    return;
  }

  // Posicion ponderada de la linea
  float error = (s1 * -3.0 + s2 * -1.0 + s3 * 1.0 + s4 * 3.0) / cuantos;
  ultimoError = error;

  float correccion = Kp * error;

  // ---------- 3. ACTUAR ----------
  int velIzq = VEL_BASE + correccion;
  int velDer = VEL_BASE - correccion;

  motorIzquierdo(constrain(velIzq, -255, 255));
  motorDerecho(constrain(velDer, -255, 255));
}

// ============================================================

void buscarLinea() {
  // Si la vio ultima vez a la izquierda, gira a la izquierda a buscarla.
  if (ultimoError < 0) {
    motorIzquierdo(-VEL_BUSQUEDA);
    motorDerecho(VEL_BUSQUEDA);
  } else {
    motorIzquierdo(VEL_BUSQUEDA);
    motorDerecho(-VEL_BUSQUEDA);
  }
}

void adelanteRecto() {
  motorIzquierdo(VEL_BASE);
  motorDerecho(VEL_BASE);
}

void frenar() {
  motorIzquierdo(0);
  motorDerecho(0);
}

void motorIzquierdo(int v) {
  if (v >= 0) { digitalWrite(IN1, HIGH); digitalWrite(IN2, LOW); }
  else        { digitalWrite(IN1, LOW);  digitalWrite(IN2, HIGH); v = -v; }
  analogWrite(ENA, constrain(v, 0, 255));
}

void motorDerecho(int v) {
  if (v >= 0) { digitalWrite(IN3, HIGH); digitalWrite(IN4, LOW); }
  else        { digitalWrite(IN3, LOW);  digitalWrite(IN4, HIGH); v = -v; }
  analogWrite(ENB, constrain(v, 0, 255));
}
🧠 Lo más lindo de este código

No tiene ningún if que diga "doblar a la izquierda" o "doblar a la derecha". Esas decisiones salieron de la fórmula. Pasaste de enumerar casos a calcular la respuesta: por eso el mismo código andaría con 6 u 8 sensores solo cambiando los pesos.

🚀 Desafíos

Medio

Montalos, calibralos uno por uno (cada potenciómetro por separado, es lo que más se saltea) y escribí un programa que muestre los cuatro por el Monitor Serie, así:

salida esperada
[ . # # . ]   error = 0.0
[ . # . . ]   error = -1.0
[ # # . . ]   error = -2.0
[ . . . . ]   PERDIDO

Pasá la mano despacio de un extremo al otro y mirá el error ir de −3 a +3. Si algún sensor nunca cambia, arreglalo ahora: el control proporcional con un sensor muerto se comporta peor que el auto de 2 sensores.

Difícil

Método sistemático, no a ojo. Con VEL_BASE = 150:

  1. Empezá con Kp = 20. El auto va a corregir poco y salirse en las curvas.
  2. Subí de a 10 hasta que complete una vuelta.
  3. Seguí subiendo hasta que empiece a zigzaguear en las rectas. Anotá ese valor: llamalo Kp_max.
  4. Tu Kp bueno está entre el que completó la vuelta y Kp_max, más cerca del segundo. Probá el punto medio y ajustá de a 5.

Después subí VEL_BASE y repetí. Vas a descubrir que Kp y velocidad están atados: más rápido necesita más Kp. Anotá los pares que funcionan.

Difícil

La función buscarLinea() ya está en el código: cuando el auto pierde la línea, gira sobre su eje hacia el lado donde la vio por última vez. Probala:

  1. Levantá el auto y sacá la línea de abajo. Tiene que empezar a girar sobre sí mismo.
  2. Volvé a ponerle la línea. Tiene que engancharla y seguir.
  3. En la pista: sacalo de la línea a propósito. ¿Vuelve solo?

Mejorala. Ideas, de menor a mayor dificultad:

  • Que la búsqueda arranque suave y se vaya haciendo más amplia con el tiempo (espiral).
  • Que si no encuentra la línea en 3 segundos, frene del todo en vez de girar para siempre.
  • Que prenda el LED de la placa mientras está perdido, para que vos veas qué está pensando.
Difícil

Elegí uno (o más) y hacelo:

  • Línea de llegada. Que detecte los 4 sensores en negro y, si es la segunda vez que lo ve, frene del todo. Cronómetro incorporado.
  • Frenado en curva. Que baje VEL_BASE cuando el error es grande y la suba en las rectas. Como frenar antes de la curva y acelerar a la salida. Es el truco que más tiempo baja.
  • Agregá la D. El término derivativo mira cuán rápido está cambiando el error y frena la corrección antes de pasarse. Es lo que elimina el zigzagueo que queda:
    correccion = Kp*error + Kd*(error - errorAnterior);
    Empezá con Kd igual a la mitad de Kp. Ahí ya estás haciendo control PD de verdad.
  • Botón de largada. Un pulsador para que el auto no arranque hasta que vos quieras. Se acabó el "salió corriendo mientras lo apoyaba".
  • Modo demo. Que muestre por el Monitor Serie el error y las dos velocidades, para poder explicarle a otro grupo qué está pensando el auto.
