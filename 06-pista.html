🏎️ Parada 6 · El ajuste

A la pista

El auto está armado y el código está cargado. Ahora empieza la parte que separa un auto que "más o menos anda" de uno que da vueltas sin fallar.

⏱️ 1h 30 – 2h 🎯 4 desafíos 🎮 Con simulador
🎯 Al terminar esta parada vas a poder…
  • Ajustar tu auto cambiando tres números y sabiendo qué hace cada uno.
  • Explicar por qué más velocidad no siempre es mejor.
  • Compensar por software que un motor sea más flojo que el otro.
  • Dar una vuelta completa a la pista sin tocar el auto.

🎮 Experimentá primero acá

Este simulador usa exactamente la misma lógica que programaste. Movele los controles y mirá qué pasa. Cada cosa que descubras acá se aplica igual a tu auto de verdad — pero acá no gastás pilas ni perseguís nada por el piso.

🤔 Buscá estas cuatro cosas en el simulador
  1. Poné la velocidad al máximo. ¿Qué pasa en las curvas cerradas? Mirá el contador de "se salió".
  2. Bajá la fuerza de corrección a 40%. El auto zigzaguea suave pero se sale en las curvas. ¿Por qué?
  3. Ahora subila a 170% (la rueda de adentro va en reversa): corrige violento y pierde velocidad en cada corrección… pero te deja subir la velocidad base sin salirte. ¿Te conviene ese cambio?
  4. Buscá la mejor vuelta posible combinando los tres controles. Anotá los valores: son tu punto de partida para el auto real. Pista: la combinación ganadora no es la de velocidad máxima con corrección normal.

⚖️ El compromiso que no se puede esquivar

Todo auto seguidor de línea vive tironeado entre dos cosas que no pueden ser máximas al mismo tiempo:

🏁 En una carrera de verdad

Gana el auto que termina, no el más rápido. Un auto que da la vuelta en 12 segundos todas las veces le gana a uno que la da en 8 pero se sale una de cada tres. Ajustá para terminar primero; la velocidad viene después.

🎛️ Los tres números que ajustás

NúmeroQué controlaSi lo subísSi lo bajás
VEL_NORMAL Velocidad en las rectas Más rápido, más riesgo de salirse Más seguro, más lento
VEL_GIRO La rueda de afuera al corregir Corrige más fuerte Corrige suave, puede no alcanzar
VEL_FRENO La rueda de adentro al corregir Giro más abierto y suave Giro más cerrado. En negativo, la rueda va en reversa y pivota en el lugar
🔬 Cambiá UNA cosa por vez

Es la regla básica de cualquier experimento, y es la que más se rompe cuando hay ansiedad. Cambiá un número, probá tres vueltas, anotá el resultado. Si cambiás tres cosas juntas y mejora, no sabés cuál lo mejoró — y cuando empeore, no vas a saber volver. Llevá una tabla escrita de cada prueba.

💻 Código con ajuste fino

Esta versión agrega dos cosas prácticas: compensación de motores desparejos (nunca son iguales) y un modo de diagnóstico por el Monitor Serie.

06_ajuste_fino.ino ⬇ .ino 
// ============================================================
//  SEGUIDOR DE LINEA - con ajuste fino
//  Todo lo que se toca esta arriba de todo.
// ============================================================

const int ENA = 5, IN1 = 6, IN2 = 7;
const int IN3 = 8, IN4 = 9, ENB = 10;
const int SENSOR_IZQ = 2, SENSOR_DER = 3;

const int VE_LINEA = HIGH;    // cambiar a LOW si tu sensor es al reves

// ---------- LOS NUMEROS QUE AJUSTAS ----------
int VEL_NORMAL = 150;   // velocidad en recta
int VEL_GIRO   = 175;   // rueda de afuera al corregir
int VEL_FRENO  = 0;     // rueda de adentro (probá -80 para giro brusco)

// Compensacion: ningun par de motores es igual.
// Si el auto se va SIEMPRE a la derecha, subi COMP_IZQ o baja COMP_DER.
float COMP_IZQ = 1.00;
float COMP_DER = 1.00;

const bool DIAGNOSTICO = false;   // true = manda datos al Monitor Serie

void setup() {
  pinMode(ENA, OUTPUT); pinMode(IN1, OUTPUT); pinMode(IN2, OUTPUT);
  pinMode(IN3, OUTPUT); pinMode(IN4, OUTPUT); pinMode(ENB, OUTPUT);
  pinMode(SENSOR_IZQ, INPUT); pinMode(SENSOR_DER, INPUT);

  if (DIAGNOSTICO) Serial.begin(9600);

  frenar();
  delay(2000);    // tiempo para soltar el auto y sacar la mano
}

void loop() {
  bool izq = (digitalRead(SENSOR_IZQ) == VE_LINEA);
  bool der = (digitalRead(SENSOR_DER) == VE_LINEA);

  if (!izq && !der) {
    motorIzquierdo(VEL_NORMAL);
    motorDerecho(VEL_NORMAL);
  } else if (izq && !der) {
    motorIzquierdo(VEL_FRENO);
    motorDerecho(VEL_GIRO);
  } else if (!izq && der) {
    motorIzquierdo(VEL_GIRO);
    motorDerecho(VEL_FRENO);
  } else {
    frenar();
  }

  if (DIAGNOSTICO) {
    Serial.print(izq); Serial.print(" "); Serial.println(der);
  }
}

// ============================================================

void frenar() {
  motorIzquierdo(0);
  motorDerecho(0);
}

void motorIzquierdo(int v) {
  v = (int)(v * COMP_IZQ);
  if (v >= 0) { digitalWrite(IN1, HIGH); digitalWrite(IN2, LOW); }
  else        { digitalWrite(IN1, LOW);  digitalWrite(IN2, HIGH); v = -v; }
  analogWrite(ENA, constrain(v, 0, 255));
}

void motorDerecho(int v) {
  v = (int)(v * COMP_DER);
  if (v >= 0) { digitalWrite(IN3, HIGH); digitalWrite(IN4, LOW); }
  else        { digitalWrite(IN3, LOW);  digitalWrite(IN4, HIGH); v = -v; }
  analogWrite(ENB, constrain(v, 0, 255));
}

🚀 Desafíos

Medio

El objetivo mínimo: que el auto dé una vuelta entera sin que nadie lo toque. Puede ir lento, puede zigzaguear, puede ser feo. Tiene que llegar.

Empezá con valores conservadores y andá subiendo:

  • VEL_NORMAL = 120
  • VEL_GIRO = 150
  • VEL_FRENO = 0
Se sale siempre en el mismo lugar de la pista

Entonces el problema no es el código: es ese pedazo de pista. Fijate si ahí la curva es más cerrada que en el resto, si hay un hueco en la cinta, si hay un reflejo o una sombra. Corregir la pista es tan válido como corregir el auto.

Medio

Casi seguro que te pasa: en las rectas el auto tira un poquito hacia un lado. No es tu código: es que los dos motores nunca son exactamente iguales, aunque sean del mismo modelo.

Arreglalo con los factores de compensación:

  • Si el auto se va a la derecha → el motor derecho es más flojo → COMP_DER = 1.10 (o COMP_IZQ = 0.90).
  • Si se va a la izquierda → al revés.

Ajustá de a 0,05 hasta que en una recta larga vaya derecho. Probalo sobre papel blanco sin línea, así ves el desvío puro sin que los sensores lo corrijan.

Difícil

Subí VEL_NORMAL de a 10 hasta que el auto se salga. Después bajá 20 y quedate ahí: ese es tu margen de seguridad. Llevá la tabla:

El truco que casi nadie descubre solo: cuando subís VEL_NORMAL, también tenés que subir la corrección — o bajar VEL_FRENO a valores negativos. A más velocidad, el auto necesita corregir más fuerte para alcanzar a doblar. Probalo primero en el simulador de arriba.

Difícil

La prueba final de esta parada: tres vueltas consecutivas sin tocar el auto, cronometradas. Anotá el tiempo de cada una.

¿La tercera fue más lenta que la primera? Bienvenido al mundo real: la batería se va descargando y con menos tensión los motores giran menos. Los equipos de competencia cargan la batería justo antes de correr por esta razón.

Extra: hacé la carrera entre equipos. Puntaje sugerido: 10 puntos por vuelta completada, −3 por cada vez que hay que tocar el auto, y un bonus al tiempo más rápido. Que la confiabilidad valga más que la velocidad.

🎒 Lo que te llevás de esta parada
  • Velocidad y estabilidad se pelean. El punto justo depende de tu pista.
  • Los motores nunca son iguales, y eso se compensa por software.
  • Un cambio por vez, y anotado.
  • Con solo 4 estados posibles, el auto corrige a los saltos. Se puede hacer mucho mejor. → Parada 7.
